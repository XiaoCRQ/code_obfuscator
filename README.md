# obfuscator

这是一个用 `c++` 编写的 `c++` 代码混淆器

## 使用方法
>
> 克隆代码并编译

- **Linux**

```bash
./setup.sh
obfuscator_cpp <file_path> <out_path>
```

## 测试

```bash
./tests/run.sh
```

脚本会用 `g++` 构建混淆器，对 `tests/cases/` 下的每个用例分别执行 token 模式、`-l`、`-n`、`-x` 和 `-t`，编译并运行结果，同时检查模式行为、临时文件清理和参数错误码。

## 可选参数

- `-x string string` 接收两套编码集，先按照词混合，再按照行混合；两套编码集都需满足下面 `-s` 的约束
- `-h string` 接受一个签名，并把它放在输出文件的头部
- `-s string` 自定义编码集，用空格隔开；至少两个互不相同、长度相同的合法标识符
- `-M number` 自定义每行最大输出字符数（≥ 1）
- `-m number` 自定义每行输出个数（≥ 1）
- `-l` 使用每行代码作为 token
- `-t` 将混淆代码翻译为原代码（仅宏展开），也可以直接翻译已经混淆过的文件
- `-n` 不使用混淆编码

## 说明

- 数字字面量（如 `1.009`、`.5`、`0x1.8p+3f`、`1'000'000`）、带前缀的字符串/字符字面量、raw string、用户自定义字面量（如 `"abc"sv`）、UCN 标识符、`...`、`<=>` 和 digraph 都会作为整体处理，不会被错误拆开。
- 多行 raw string 以及行模式下含 raw string 的行会原样输出，不参与混淆，以保证内容逐字节不变。
- token 模式的 `(`、`)`、`,` 保持原样，确保头文件中 `va_start`、`assert`、`offsetof` 之类的函数式宏仍能被正确展开。
- 混淆结果依赖文件头部的 `#define`，不是独立的 C++ 源码；混淆器通过 `g++ -E -P` 预处理，因此需要 `g++` 在 `PATH` 中。
